# Dev Log

## 2026-07-28

Shipped 0.2.0, whose headline is a behavior change: backends no longer inject a system prompt unless the caller asks for one. Every API backend had been defaulting `role_description` to a fiction-writing persona ("You are a helpful fiction writing assistant. You will create original text only."), and the registry never forwarded the parameter, so every call through `send_prompt()` silently shipped that persona with no override. Fine for the family's original novel-writing consumers, wrong for anyone else, and actively harmful for a coding agent, where "create original text only" surfaces as mysterious refusals rather than an obvious misconfiguration. The default is now `None` (no system prompt at all, not a neutral replacement) across all five API backends, and `role_description` is threaded through the 20 registry lambdas and the whole `send_prompt` family. The day's second commit finished the job on the singleton `llm_interface` path, which had no way to opt a persona back in: `MultiProviderInterface` and `initialize_llm` now carry an instance-level `role_description`, and the previously-missed `send_prompt_with_retry` was wired up too. Version bumped 0.1.1 → 0.2.0 with a CHANGELOG entry; 98 tests pass.

**Decisions & notes:** Silence was chosen over a neutral placeholder persona deliberately, and it makes Gemini's prior behavior (which accepted no system prompt) the standard rather than the anomaly; Gemini gained `system_instruction` so the same registry call now behaves the same everywhere, Anthropic omits the `system` kwarg entirely (the API rejects `system=None`), and OpenAI-shaped backends omit the system turn. Callers wanting the old behavior restore it in one line via the exported `FICTION_ROLE`: `send_prompt(..., role_description=FICTION_ROLE)` or `initialize_llm(backend="api", role_description=FICTION_ROLE)`. Passing `role_description` to a CLI backend raises RuntimeError rather than dropping it silently, since CLI backends have no system-prompt concept. One subtle implementation note: `_call_model_fn` was made to degrade per-kwarg rather than all-or-nothing, because the naive "try both kwargs else the bare call" fix would silently drop `timeout` for any registry entry that accepts `timeout` but not `role_description` (there's a test guarding this). Adopters whose facades already pass `role_description` explicitly (NovelWriter, the analyzer, PIT, CryptoAlertBot) are unaffected; only consumers relying on the old implicit persona must now opt in.

## 2026-07-15

The `llm-backends` package was born and hardened in a single day. It started as an extraction from StoryDaemon (initial 0.0.1 drop), then went through the big "hardening merge" that absorbed the analyzer and NovelWriter backend variants into one coherent library (0.1.0), followed by two quick follow-ups to fix a fallback-model footgun and restructure the README (0.1.1). The through-line was consolidating three divergent copies of the same LLM-backend code into a single package with a unified model registry, provider hardening, and a real test suite (38 to 85 tests over the day).

**Decisions & notes:** The headline behavior change for adopters is that CLI-agent backends now strip their provider's API key(s) from a copy of the environment by default (`strip_provider_keys=True`), so agent CLIs authenticate via their own login instead of silently billing metered keys; the opt-out is per-interface. The merge unified 20 primary models plus an alias table covering StoryDaemon and NovelWriter spellings behind a public `resolve_model()`, made `ANTHROPIC_API_KEY` canonical while still honoring `CLAUDE_API_KEY` with a one-time DeprecationWarning, and added a Codex bubblewrap/user-namespace workaround for hardened Linux plus OpenRouter client hardening (retries, timeout, `openrouter:<upstream>` prefix passthrough). Several merges were deliberately *not* taken and recorded as such: the analyzer's app-level `*-cli` registry keys, its `max_tokens` default change, and NovelWriter's `claude-4-5-opus` alias (all deferred to later migration steps to avoid silently perturbing frozen defaults or upgrading models). NovelWriter's ignored-timeout bug was intentionally not copied. Consumers now read `llm_backends.DEFAULT_API_MODEL` instead of hardcoding `"gpt-5.5"` fallback literals in multiple files. The whole suite passes in an SDK-free venv, preserving the lazy-import contract.
